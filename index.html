Team project

Okane Transfer, in detail

Okane covers a transfer from the counter to the payout. An agent registers it between two clients, the platform prices it from the corridor's pricing grid and issues a payout code, and the beneficiary collects against that code. Every step feeds the agent's daily cash register, the audit journal and the client's tracking view.

15entities
103API endpoints
3roles
4transfer statuses

Who uses it

Admin runs the network

  • Creates, activates and deactivates users
  • Agencies, countries, currencies, corridors
  • Pricing grids: amount range, fixed cost, fee, agency share
  • Dashboard and audit journal

Agent at the counter

  • Creates transfers, cash or mobile money
  • Pays out by code
  • Cancels pending transfers
  • Opens and closes a daily cash register

Client follows it

  • Registers and verifies email
  • Sent and received transfers
  • Lookup by payout code
  • Notifications and a chat assistant in French, English and Arabic

Transfer lifecycle

PENDINGcreated + code
pay by codePAID
cancelCANCELED
expireEXPIRED
  • The amount must be positive, and the sender cannot also be the beneficiary.
  • Only a pending transfer can be paid, and a paid transfer cannot be canceled.
  • Each transfer keeps its notifications, audit entries and cash movements.

Engineering

Spring without Boot

Plain Spring 6 packaged as a WAR for Tomcat, with the servlet setup, security chain, persistence and Swagger configured by hand.

Stateless JWT

A token filter runs ahead of Spring Security. Admin routes need ADMIN, agent routes AGENT or ADMIN, client routes CLIENT or ADMIN.

Rules live in services

Controllers call service interfaces over Spring Data repositories, with request and response DTOs, Bean Validation and transactions.

Cash and audit

Daily registers per agent with opening and closing balances, sending and payout movements, and an audit journal queryable by transfer, agent or agency.

Documented API

SpringDoc generates the OpenAPI spec and a Swagger UI page, with written docs for corridors, currencies and pricing grids.

Deployed build

Hugging Face blocks SMTP, so email goes through Brevo's HTTP API. Exchange rates come from an external API and are cached in memory.
